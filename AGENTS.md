# AGENTS.md

Fork of pulp-platform/pulpissimo (single-core RISC-V SoC, SystemVerilog). Current branch: `public-viriscv`; origin is an internal GitLab (`172.16.10.117:cica/viriscv.git`). Local additions on top of upstream: Arty A7-100T FPGA port (`target/fpga/pulpissimo-arty/`) and a repo-local PlatformIO platform (`platformio/`).

## Dependencies: Bender, not just submodules

- RTL IPs are fetched with Bender (`Bender.yml` / `Bender.lock`), installed to `utils/bin/bender` by `make checkout`, and checked out into `.bender/git/checkouts/`. Never edit files there.
- To modify a dependency IP: `./utils/bin/bender clone <ip>` (creates an editable copy in `working_dir/`), then `make scripts` and `make build`. To swap in a fork, edit `Bender.yml` and run `./utils/bin/bender update`.
- `sw/pulp-runtime` and `sw/regression_tests` are git submodules and are empty until `git submodule update --init --recursive`.
- `sw/pulp-runtime` is pinned to public commit `ad0f614`; the private PULPissimo config delta (FPGA freq 10 MHz, smaller L2, I2S/tracer disabled) is vendored as `sw/patches/pulp-runtime/0001-Update-PULPissimo-FPGA-configuration.patch`. Apply it after checkout when matching the private branch behavior.

## Generated RTL is committed — regenerate, don't hand-edit

- `hw/asic_autogen_rom.sv` and `hw/fpga_autogen_rom.sv`: boot ROMs compiled from `sw/bootcode` (`make bootrom`).
- `hw/padframe/pulpissimo_padframe_{rtl_sim,fpga}_autogen/`: generated by padrick from `hw/padframe/*.yml` (`make padframe`).
- GPIO IP is vendored under `hw/vendored_ips/gpio` (not a Bender dep) so it can be regenerated for a different pin count: `make gpio-reconfigure GPIO=32`.
- `make hw` regenerates all of the above.

## Simulation (QuestaSim only)

- Out of the box only QuestaSim/Xcelium work; no ModelSim (Intel variant) or Verilator target. CI uses Questa 2023.4.
- Build order matters: `make checkout` → `make build` (creates `build/questasim`). `make scripts` only regenerates the Bender→TCL compile scripts.
- Run one ELF: `make run_sim EXECUTABLE_PATH=/abs/path/to/elf` (converted to SREC via `riscv32-unknown-elf-objcopy`). GUI mode: `make run_sim gui=1` (lowercase — the Makefile checks `$(gui)`, not the documented `GUI` param). `make help` lists documented targets.
- Optional commercial VIP models (SPI flash, I2C, I2S) under `target/sim/vip/`, fetched with `./target/sim/vip/get-vips.sh --yes`, enabled with `USE_VIPS=1`.

## Tests

- No unit-test framework; tests are firmware run in simulation. The real regression suite runs on ETH's internal GitLab (`.gitlab-ci.yml`); the GitHub workflow only mirrors it, so PRs from forks don't execute tests.
- Run a single test locally (after `make build`):
  ```sh
  source sw/pulp-runtime/configs/pulpissimo_cv32.sh
  export VSIM_PATH=$PWD/build/questasim
  make -C sw/regression_tests/<test> clean all run
  ```
  (e.g. `sw/regression_tests/hello`, `riscv_tests/testALU`, `sequential_bare_tests/fibonacci`).
- Lint (CI): `make lint_rtl` — Spyglass, needs the Spyglass tool; config in `target/lint/spyglass/`.

## FPGA vs simulation software configs differ — match them or builds misbehave

- Arty A7 FPGA: CV32E40P with **Zfinx enabled**, fixed 10 MHz SoC / 5 MHz peripheral clocks, no FLL reconfiguration → source `sw/pulp-runtime/configs/pulpissimo_cv32_zfinx.sh`.
- Default sim testbench `tb_pulp`: CV32E40P with FPU but **Zfinx disabled** → source `configs/pulpissimo_cv32.sh`.
- FPGA-mode app builds hit a missing-include bug in the runtime; work around with:
  ```sh
  export PULPRT_CONFIG_CFLAGS="-I$PWD/sw/pulp-runtime/drivers/pulpissimo/rtl_sim/io_mux/include"
  make -C sw/regression_tests/hello clean all platform=fpga
  ```

## FPGA builds

- Bitstreams: `make arty rev=artyA7-100T` (also genesys2, zcu104, zcu102, zcu106, nexys[_video], vcu108, zedboard) from repo root or `target/fpga/`. Requires Vivado; override binary with `VIVADO='...'`.
- Output lands in `target/fpga/pulpissimo_<board>.{bit,bin}`.
- Arty needs two JTAG chains: onboard Digilent PROG USB programs the FPGA (`xc3sprog -c nexys4 ...`); the PULPissimo JTAG is on PMOD A and needs an external adapter (Olimex/HS2) with the PULP-patched OpenOCD. Upstream riscv-openocd does not work (hart 992 issue). Verified end-to-end flow: `target/fpga/pulpissimo-arty/RUN_ARTY_A7_100T.md`; sim-vs-FPGA differences: `FPGA_VS_SIMULATION.md` in the same dir.

## PlatformIO (repo-local platform, Arty A7-100T)

- Uses the checked-out `sw/pulp-runtime`, not the outdated registry platform. Requires `PULP_RISCV_GCC_TOOLCHAIN` set, then `source platformio/env.sh` (sets `PULPISSIMO_ROOT`, `OPENOCD=build/tools/openocd`, per-checkout platform dir `.pio-platforms/`).
- Build all examples: `make platformio-examples` (override `PIO=` if pio isn't on PATH). Hardware smoke tests on a programmed board: `make platformio-smoke UART_PORT=/dev/ttyUSB2` — close any serial monitor first; the runner takes exclusive ownership of the port.

## Conventions

- Makefile targets/params must be documented with the `## @param` / `## @section` comment style (see `utils/utils.mk`, `target/sim/questasim/Makefile`) so they appear in `make help`.
- New simulation environments must expose a `run_sim` target honoring `EXECUTABLE_PATH` (mandatory) and `GUI`/`BATCH` (optional) env vars — see `target/sim/README.md`.
- Bender target tags select platform sources: `rtl_sim`/`simulation` for sim, `fpga`+`xilinx` for FPGA (see `Bender.yml`); keep new RTL files registered under the right target.
- Contributions are PRs against the fork/upstream; coding style follows the PULP/ariane CONTRIBUTING guidelines (loosely enforced).
